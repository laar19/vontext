**Propósito de este documento:** Servir como guía completa para que una IA desarrolle una aplicación Android nativa que replique la funcionalidad del proyecto original de Python/Docker.

## 1. Resumen Ejecutivo

VideoContextBot es un sistema de procesamiento de videos de grabaciones de pantalla que genera contexto enriquecido para agentes de IA. La aplicación Android debe replicar las siguientes funcionalidades principales:

1. **Subida de videos** desde el dispositivo Android
2. **Detección automática de pista de audio**
3. **Extracción inteligente de frames únicos** (detección de escenas o por intervalo)
4. **Transcripción de audio** usando APIs compatibles con OpenAI Whisper
5. **Generación de PDF profesional** con frames y transcripción
6. **Descarga de ZIP** con todos los archivos de output
7. **Seguimiento de progreso** en tiempo real

```kotlin
// Usar MediaMetadataRetriever o MediaExtractor
fun hasAudioTrack(videoPath: String): Boolean {
    val retriever = MediaMetadataRetriever()
    retriever.setDataSource(videoPath)
    val hasAudio = retriever.extractMetadata(MediaMetadataRetriever.METADATA_KEY_HAS_AUDIO)
    return hasAudio == "yes"
}
```

#### Extracción de Frames

**Opción A: Detección de Escenas (Recomendado)**
- Usar biblioteca como `SceneDetect` portada a Kotlin/Java
- O implementar detección de cambios de histograma con OpenCV Android

**Opción B: Por Intervalo**
```kotlin
fun extractFramesByInterval(videoPath: String, intervalSeconds: Int): List<FrameInfo> {
    val retriever = MediaMetadataRetriever()
    retriever.setDataSource(videoPath)
    val duration = retriever.extractMetadata(MediaMetadataRetriever.METADATA_KEY_DURATION).toLong()
    
    val frames = mutableListOf<FrameInfo>()
    var currentTime = 0L
    
    while (currentTime < duration) {
        val bitmap = retriever.getFrameAtTime(currentTime * 1000, OPTION_CLOSEST)
        // Guardar bitmap como JPG
        currentTime += intervalSeconds * 1000
    }
    
    return frames
}
```

**Límites:**
- Mínimo: 10 frames
- Máximo: 50 frames
- Si excede 50, subsamplear equidistantemente

### 3.5 Creación de ZIP

```kotlin
fun createZip(outputFolder: File): File {
    val zipFile = File(outputFolder.parent, "${outputFolder.name}.zip")
    ZipOutputStream(FileOutputStream(zipFile)).use { zos ->
        outputFolder.walkTopDown().filter { it.isFile }.forEach { file ->
            val entry = ZipEntry(file.relativeTo(outputFolder.parent).path)
            zos.putNextEntry(entry)
            file.inputStream().copyTo(zos)
            zos.closeEntry()
        }
    }
    return zipFile
}
```

**WorkManager para procesamiento asíncrono:**

```kotlin
class VideoProcessingWorker(
    context: Context,
    params: WorkerParameters
) : CoroutineWorker(context, params) {

    override suspend fun doWork(): Result {
        val jobId = inputData.getString("job_id") ?: return Result.failure()
        
        // Actualizar progreso
        setProgress(workDataOf("progress" to 10, "message" to "Analizando video..."))
        
        // Ejecutar procesamiento
        val result = processVideo(jobId)
        
        return if (result.success) Result.success() else Result.failure()
    }
}
```

## 11. Estrategias de Implementación

### Opción A: App Nativa con Procesamiento Local (Recomendado para privacidad)

**Ventajas:**
- Sin dependencia de servidor
- Procesamiento offline
- Mayor privacidad

**Desventajas:**
- Mayor consumo de batería
- Limitaciones de hardware del dispositivo
- APIs de Whisper requieren conexión (si no se usa modelo local)

### Opción B: App Cliente + Backend Existente

**Ventajas:**
- Reutiliza infraestructura actual
- Procesamiento más rápido en servidor
- Menor consumo en dispositivo

**Desventajas:**
- Requiere conexión constante
- Dependencia del servidor

### Opción C: Híbrida

- Procesamiento local de frames y PDF
- Transcripción vía API externa (Groq/OpenAI)
- Opcionalmente conectarse al backend existente para jobs pesados

## 16. Notas Finales

### 16.1 Diferencias Clave con el Proyecto Original

1. **Sin Docker:** La app Android es standalone
2. **Sin Celery/Redis:** Usar WorkManager en su lugar
3. **Sin Telegram Bot:** Reemplazado con notificaciones push nativas
4. **Sin Gradio:** UI nativa con Compose
5. **SQLite local:** En vez de SQLite en volumen Docker

### 16.2 Mejoras Potenciales sobre el Original

1. **Procesamiento offline:** Sin dependencia de internet (excepto Whisper API)
2. **Notificaciones nativas:** Mejor UX que Telegram
3. **Historial local:** Acceso rápido a jobs anteriores
4. **Compartir directamente:** Integration con otras apps Android

### 16.3 Limitaciones a Considerar

1. **Batería:** Procesamiento de video consume mucha energía
2. **Calor:** Dispositivos pueden calentarse con procesamiento largo
3. **Memoria:** Limitada comparada con servidor
4. **Almacenamiento:** Videos de 2GB ocupan espacio significativo
